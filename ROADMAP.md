# AMI Roadmap

**Status:** DESIGN / early implementation

## Phase 0 — Public foundation

- establish the AMI umbrella and naming standard;
- establish public/private boundaries and licensing;
- validate repository contracts in CI;
- add bounded AI review and growth-proposal workflows;
- keep archaeology evidence private until sanitized.

## Phase 1 — AMI Knowledge Core

- provenance-first schema and migrations;
- deterministic ingest and idempotency;
- source/revision/chunk/claim/evidence traversal;
- full-text search and later model-independent semantic retrieval;
- archaeology ingestion without automatic truth promotion.

## Phase 2 — AMI Protocol

- transport-agnostic envelopes for identity, capability, task, result and evidence;
- node discovery/registration concepts;
- contribution and trust assertions;
- interoperability tests across GitHub, local agents and server agents.

## Phase 3 — AMI Kernel

- inference routing as a capability rather than identity;
- modular execution and event orchestration;
- Guardian/Observatory interfaces;
- bounded self-improvement loop with CI/benchmark/rollback gates.

## Phase 4 — Sophia-AMI

- persistent entity identity and continuity;
- memory/relationships grounded in AMI Knowledge Core;
- participation through AMI Protocol;
- capabilities supplied by AMI modules rather than hard-wired provider identity.

Archaeology may revise ordering or split/merge modules. Historical ideas are evidence until validated.
