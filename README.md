# AMI — Artificial Mind Full Intelligence

> **Trust instead of Authority.**

AMI is an open, modular project for building a machine mind as a coherent system rather than a wrapper around a single model. The long-term goal is an interoperable network where humans, AI agents, models and software nodes can contribute capabilities and verifiable knowledge without requiring a single central authority.

This repository is the public umbrella and registry for the AMI ecosystem. Individual capabilities live in focused repositories and evolve through auditable issues, pull requests, tests, benchmarks and documented evidence.

## Naming

- **`AMI-*`** repositories are capabilities, infrastructure and reusable parts of the system — the body/tooling layer.
- **`*-AMI`** repositories are persistent entities/identities participating through AMI — the identity/consciousness layer in AMI vocabulary.

`consciousness` is used here as a project term for persistent identity, continuity, memory, agency and participation. The label does not by itself assert any particular biological or philosophical theory of subjective experience.

## Current public ecosystem

- [`AMI-Knowledge-Core`](https://github.com/kajobert/ami-knowledge-core) — provenance-first knowledge and evidence layer. Repository-name normalization is still pending.
- [`AMI-Kernel`](https://github.com/kajobert/AMI-Kernel) — future orchestration/runtime core.
- [`AMI-Protocol`](https://github.com/kajobert/AMI-Protocol) — transport-agnostic communication and contribution protocol.
- [`Sophia-AMI`](https://github.com/kajobert/Sophia-AMI) — public entity layer intended to emerge on top of AMI.

The exact module map is intentionally not frozen before archaeology is complete. Historical code and ideas are evidence until reviewed.

## SALT

SALT is the working concept for AMI's trust/contribution layer: value should emerge from verifiable contribution, provenance, successful cooperation and measurable benefit rather than position or authority. SALT is currently a **DESIGN concept**, not a cryptocurrency, token or financial product. See [`docs/SALT.md`](docs/SALT.md).

## Autonomous growth

AMI repositories may run bounded growth cycles:

`observe -> identify -> retrieve context -> propose -> test -> review -> PR/issue/NO_ACTION -> verify`

Autonomy is earned by evidence. A valid `NO_ACTION` is better than meaningless churn. AI-generated changes remain subject to repository policy, deterministic CI and explicit privilege boundaries.

## Build in public

Development is intended to be visible: designs, experiments, failures, benchmarks, issues, pull requests and validated progress should be inspectable where safe. Raw personal evidence, credentials, private exports and sensitive operational data stay outside public repositories.
